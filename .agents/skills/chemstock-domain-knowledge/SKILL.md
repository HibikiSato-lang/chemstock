# ChemStock ドメイン知識

ChemStockは大学の研究室・溶媒庫向けの**溶媒**在庫管理システム。薬品全般ではなく、溶媒に対象を絞っている。
紙の記録簿の置き換え（デジタイゼーション）は完了しており、現在は指定数量監視・欠品予測などの
デジタライゼーション機能を拡張する段階（背景は [docs/DX構想.md](../../../docs/DX構想.md)）。

このドキュメントは**要点のクイックリファレンス**。詳細設計は必ず一次情報を読むこと：
- データモデルの正: [docs/ER図.md](../../../docs/ER図.md)
- 画面・デザインの正: [docs/UI案.md](../../../docs/UI案.md)
- 法令の背景知識（数値を丸暗記しない）: [references/fire-law.md](references/fire-law.md)

## 1. データモデルの要点

| エンティティ | 役割 | 見落としがちな点 |
|---|---|---|
| `rooms` | 研究室 or 溶媒庫 | `kind` の違いが指定数量集計の単位そのもの。溶媒庫＝保管拠点、研究室＝使用者 |
| `accounts` | ログイン主体 | **研究室単位の共有アカウント**。個人ログインではない。`role`は研究室/溶媒庫管理/全体管理者 |
| `solvents` | 溶媒マスタ（全体共通） | `designated_quantity`（指定数量）は法令値。この値をアプリ側で決め打ちしない |
| `inventory` | room×solventの現在庫 | `low_stock_threshold`（下限）と`is_active`（利用停止）を持つのは在庫側、マスタ側ではない |
| `inventory_logs` | 入出庫履歴 | `operator_name`は**手入力必須**（共有アカウントのため個人を追えない）。`status`で取消管理 |
| `operation_audits` | 監査ログ | 取消・編集・利用停止・しきい値変更は**すべて**ここに before/after と reason を記録する |
| `notifications` | 在庫下限・指定数量通知 | `status`（未確認/確認済/対応済）で運用。研究室ユーザーには見せない種類がある |
| `settings` | 全体設定 | `warning_ratio`(0.8)など。法令上の閾値とは別物（§3参照） |

## 2. 破ってはいけない業務ルール

実装や設計を提案する前に、次のルールと矛盾していないか必ず確認する。

1. **物理削除しない**：入出庫の取消・編集・マスタの利用停止は、対象レコードの`status`や`is_active`を変更し、`operation_audits`に変更前後の値と理由を残す。DELETE文で消してはいけない。
2. **指定数量の合算は溶媒庫単位**：`rooms.kind = '溶媒庫'`の在庫だけを`Σ(amount ÷ designated_quantity)`で合算する（研究室が自室で保管する分を含めるかは[未確定事項](../../../docs/ER図.md)）。
3. **可視性の非対称**：研究室ユーザーは自分の`room_id`の在庫しか見えない。指定数量の合算倍率・通知は管理者向けであり、研究室ユーザーには見せない。
4. **実操作者名は手入力**：共有アカウントなのでログインユーザー＝操作者ではない。過去入力のサジェスト表示は良いが、自動補完で確定してはいけない。
5. **単位は`base_unit`で内部保持**：`inventory.amount`は常に基準単位。表示時のみ`settings`の換算値でL/gal等に変換する。amountに複数単位を混在させない。

## 3. UI/UX規範の要点

- **スマホ前提・スクロール最小化**が必須方針（下部タブバー / プルダウン / 折りたたみを使う）。
- 下部タブバー5項目（ホーム／登録・使用／在庫／グラフ／管理）はログイン画面以外の全画面で固定。管理タブ内の管理者専用項目のみロールで出し分け、タブ自体は5つで固定。
- デザイントークン：背景ミントグリーン`#D5EBE1`、主ボタン濃緑`#2E6B58`＋白文字、白カード＋細いグレー罫線。
- **既存画面のフロー・コードは変更しない**のが大原則。新機能は「タブバーに1項目追加」「詳細情報に行を1行追加」のような差分として設計する。
- 危険な操作（取消・利用停止・しきい値変更）は確認ダイアログを挟む。

## 4. 消防法・指定数量の基礎知識

有機溶媒の多くは消防法上の危険物（第4類：引火性液体）に該当し、「指定数量」を基準に規制がかかる。
**具体的な数値や分類をこのスキルが決め打ちしてはいけない**——`solvents.designated_quantity`に格納された値を正とする。
制度の考え方（倍数計算・閾値の意味）は [references/fire-law.md](references/fire-law.md) を参照。
特に、`settings.warning_ratio`(0.8)は法令上の届出基準ではなく、**ChemStock独自の早期警告閾値**である点を混同しないこと。

## 5. 実装時の判断基準

- 新機能を思いついたら、まず既存カラム・既存テーブルの拡張で実現できないか検討する（ER図は将来拡張を見込んだ設計になっている）。
- 迷ったら「これは研究室ユーザーにも見せてよい情報か、管理者限定か」を最初に確認する。
- DB変更を伴う提案をするときは、`docs/ER図.md`の該当箇所を引用し、矛盾がないか明示する。
