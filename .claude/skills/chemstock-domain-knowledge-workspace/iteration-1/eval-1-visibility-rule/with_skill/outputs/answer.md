# 指定数量の倍数が0.8を超えた場合の警告バナー：表示対象は管理者限定にすべき

## 結論

**管理者専用にすべきです。研究室ユーザーの画面には出さないでください。**

これはChemStockの既存の業務ルールに明記されている方針であり、新たに検討するまでもなく従うべきガードレールです。

## 理由

### 1. 「可視性の非対称」ルールに明確に抵触する

ChemStockには次の業務ルールがあります。

> 可視性の非対称：研究室ユーザーは自分の`room_id`の在庫しか見えない。**指定数量の合算倍率・通知は管理者向けであり、研究室ユーザーには見せない**。

「指定数量の倍数が0.8を超えたら警告」という機能は、まさにこの「指定数量の合算倍率」そのものです。したがって設計上、研究室ユーザーの画面に出すことはルール違反になります。

### 2. 合算の単位が「研究室」ではなく「溶媒庫」であるため、他研究室の情報が漏れる

指定数量の倍数は、`rooms.kind = '溶媒庫'`の在庫だけを対象に`Σ(amount ÷ designated_quantity)`で**溶媒庫単位**で合算する設計です。溶媒庫は通常、複数の研究室が共同で利用する保管拠点であり、特定の研究室だけの数値ではありません。

そのため、もしこの倍率や警告バナーを研究室ユーザーに見せてしまうと、

- 自分の研究室の使用量だけでなく、**他研究室を含めた全体の保管状況を類推できてしまう**
- 研究室ユーザーは自分の`room_id`の在庫しか見えないという原則（アクセス制御の前提）と矛盾する

という問題が生じます。これは単なる「情報を見せすぎる/見せなさすぎる」というUXの話ではなく、アクセス制御の設計原則に反する情報漏洩です。

### 3. `warning_ratio`（0.8）は法令基準ではなく、あくまで「管理者が消防法対応を判断するための」独自閾値

`settings.warning_ratio`（デフォルト0.8）は消防法上の届出基準ではなく、「指定数量の倍数が1.0（法令上の届出・許可ラインの目安）に近づく前に気づけるようにする」ためのChemStock独自の早期警告閾値です。

この数値は、溶媒庫全体の在庫を消防法上どう管理するか（少量危険物の届出対応、施設全体の許可対応など）を判断するための情報であり、判断・対応の主体は大学の安全管理担当・溶媒庫管理者です。研究室ユーザーが個々の判断で対応できる性質のアラートではないため、通知先を管理者に絞るのが業務上も自然です。

### 4. `notifications`テーブルの設計とも整合する

データモデル上も、「`notifications`（在庫下限・指定数量通知）は`status`（未確認/確認済/対応済）で運用し、**研究室ユーザーには見せない種類がある**」とされています。指定数量に関する通知は、この「研究室ユーザーには見せない種類」に該当するものとして設計されているべきです。

## 研究室ユーザー側に何も出さなくてよいか（補足）

研究室ユーザーに完全に何も伝えないのが業務上不自然に感じる場合は、以下のように**情報の粒度を変えて**切り分けることを検討してください（今回のルール変更ではなく、別機能としての提案です）。

- 研究室ユーザーには、**自分の研究室の在庫が`low_stock_threshold`（下限）を下回った**旨の通知（＝在庫側の既存概念）は見せてよい。これは指定数量倍率とは別物であり、可視性ルールにも抵触しません。
- 「指定数量の倍数が0.8を超えた」という消防法がらみの警告は、**溶媒庫管理者・全体管理者**（`accounts.role`）のみに表示するバナー・通知として実装する。

## UI実装上の位置づけ

UI規範では「下部タブバー5項目は固定、管理タブ内の管理者専用項目のみロールで出し分け」とされています。この警告バナーも同様に、画面自体は共通にしつつ、**表示コンポーネントをロール（`accounts.role`）で出し分ける**形で実装するのが、既存のUI設計方針と整合的です。既存画面のフロー・コードを変更しないという原則にも合致し、「管理タブ内、または管理者ロール時のみ表示されるバナーを1つ追加する」という小さな差分として設計できます。
