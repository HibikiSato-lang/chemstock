追加機能の操作フロー

実装した画面を、日々の入出庫から欠品予測・指定数量の確認まで、操作する順番で説明するための資料です。

コード実装・ローカル検証済み予測方式は再検討中実Supabaseの通し確認前リリース判定前
操作できるプレビューを開く全画面の遷移マップを見るDXとの関係を読む

見る前に

このHTMLは単体で閲覧できます。操作を試す場合はリポジトリで npm ci → npm run dev を実行し、上のボタンから http://localhost:3000/preview を開いてください。プレビュー画面上部で「研究室」「溶媒庫管理」「全体管理者」を切り替えられます。

プレビューはサンプルデータで、操作内容はそのブラウザー内に保存されます。実在庫やSupabaseへは書き込みません。日付・数量はサンプルと操作結果によって変わります。

1. 入出庫と履歴全ロール・権限内の研究室 2. 欠品予測所属・選択研究室の在庫 3. 指定数量通知管理者のみ・全研究室合算 4. 管理対象と設定操作ごとに権限を確認

主要な操作手順

日常操作

1. 入出庫を記録し、履歴で確認する

共有アカウントなので、保存のたびに実際に操作した人の名前を入力します。研究室・溶媒庫管理のアカウントでは対象研究室を所属から決め、全体管理者だけが研究室を選択します。

  1. ホームから「入庫・使用を記録」
    /preview
  2. 「残量調整」で溶媒を選択
    /inventory/adjust
  3. 追加／使用、正の数量、単位、実操作者を入力
    /inventory/action/add
  4. 現在量・変量・更新後残量を確認して実行
    …/confirm
  5. 完了後、履歴で記録を確認。誤りは理由を添えて訂正・取消
    /inventory/history
数量の符号は「追加／使用」から決まり、負数の入力は保存前に止めます。後日登録には実際の入出庫日時を指定できます。訂正・取消は元の履歴を消さず、監査記録を残します。
この操作から試す →
DXコア F2

2. 下限到達の見込みを確認する

所属研究室（全体管理者は選択した研究室）の有効な出庫履歴から直近N日間の平均使用量を計算し、在庫下限に達する時期を見積もります。これは見通しの表示であり、発注を自動で決める機能ではありません。

  1. ホームの「在庫のお知らせ」を見る
    /preview
  2. 気になる溶媒の行を開く
    /inventory/detail/…
  3. 下限値と現在量を確認
    在庫詳細
  4. 「グラフ」タブで溶媒・期間を選ぶ
    /graph
  5. 実績線、下限線、予測線・予測日を読む
    同じグラフ画面
出庫実績がない、下限未設定、すでに下限以下、または到達が365日超の場合は予測日を出しません。下限以下はホーム・在庫一覧に状態として表示し、管理者向け通知は作りません。

現行の予測日は「設定した期間の平均使用ペースが続く場合」の計算結果です。記録開始直後やまとめ出庫では日付が実際の使用予定を表さないため、計算と表示の方法を再検討中です。

DXコア F1・管理者のみ

3. 指定数量の超過を確認・対応する

溶媒庫にある全研究室の利用中在庫を合算して倍率を表示します。既定の0.8倍はChemStock独自の接近表示で、1.0倍以上になると管理者向けアプリ内通知を記録します。

  1. 管理タブの未確認件数を見る
    /manage
  2. 「管理者画面」を開く
    /manage/admin
  3. 「通知一覧」で未確認通知を読む
    …/notifications
  4. 「現在の倍率を見る」でモニターへ
    …/designated-quantity
  5. 確認済み・対応済みへ変更し、件数の更新を確認
    通知一覧
通知の倍率は発生時点の値、モニターの倍率は現在値です。研究室ユーザーには倍率・通知を表示しません。メール・SMS・プッシュ通知は初回リリースの確認対象ではありません。
管理者の通知画面を開く →
管理操作

4. 管理する溶媒を追加・再開し、設定を確認する

管理対象の追加・再開は所属研究室の範囲で行います。全体管理者は溶媒マスタの登録・指定数量の変更と、警告倍率・予測期間の変更もできます。

  1. 管理タブから「溶媒種類管理」
    /manage/types
  2. 「溶媒を追加」で既存マスタを選ぶ
    …/types/new
  3. 実操作者名と理由を入力し、追加・再開
    管理対象
  4. 全体管理者はマスタ・設定を開く
    …/admin/master・settings
  5. 保存後、対象研究室の在庫と現在の倍率を確認
    在庫・モニター
利用停止は残量0 Lの在庫に限ります。停止・再開しても履歴を物理削除しません。指定数量は溶媒マスタの値を使い、早期警告倍率とは別に扱います。

追加機能はどのようにDXにつながるか

まず入出庫を正確に記録し、実操作者と変更理由を残すことで、在庫と履歴を判断に使えるデータにします。そのデータから、次の2つの判断を支援します。

  1. 指定数量監視 F1：溶媒庫全体の倍率を入出庫のたびに再判定し、超過時は管理者が通知を確認・対応します。人が定期的に計算して異常を探す仕事から、システムの判定を受けて対応する仕事へ移る入口です。
  2. 下限到達の目安 F2：研究室の過去の出庫を使い、「このペースが続けばいつ下限に近づくか」を示す現行実装です。実験予定は入力していないため、次のまとめ出庫日は予測できません。早めの確認に役立つ表示へ再設計中です。
共有会での説明例：「今回は、紙の記録を画面に置き換えるだけでなく、蓄積した入出庫から指定数量の超過を管理者へ示し、研究室には下限到達の目安を示します。記録を見て人が気づく業務から、システムの提示を受けて人が判断・対応する業務への一歩です。ただし、機能を作っただけでDXが完成したわけではありません。現場で記録と確認が定着し、見逃しや対応の遅れが減ったかを検証します。」

現在確認できたのは画面・DB処理のローカル実装です。対応時間、見逃し、記録の定着率、予測の有用性などの運用効果は未測定です。大学全体の運用変革には複数研究室の定着と管理主体の合意が必要です。

下限予測の表示方法を再検討中

現行式は「直近N日の出庫量 ÷ N」を1日あたりの使用量とし、現在量から下限までの差をその値で割ります。分かりやすい反面、開始3日で3 L使った場合もN=30日で割るため、少ない履歴で下限到達を遅く見積もることがあります。

分母を観測日数に変えるだけでは、実験日にまとめて使う在庫の次回出庫時期は分かりません。初回リリースの提案は、下限までの余裕量と「直近の最大出庫と同量なら何回で下限に届くか」を示し、到達日はいったん表示しない方式です。日付は実績で有用性を確かめてから条件付きの試算として追加します。現行コードと要件定義はまだ変更していません。

リリース前の残件

  • 予測の表示目的・計算方法を決め、要件定義と実装に反映する
  • 実Supabase開発環境で、追加→初回入庫→履歴→倍率・予測まで通しで確認する
  • 別端末への更新反映、通信結果不明時の再試行、実スマートフォンでの表示を確認する

予測方式の運用上の妥当性評価、実Supabaseへのマイグレーション適用と実機の通し試験は未実施です。これらが終わるまでリリース完了とは扱いません。
