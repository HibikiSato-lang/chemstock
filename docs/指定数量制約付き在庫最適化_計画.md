# 指定数量を制約とする在庫最適化の計画

作成日：2026-10-12。状態：計画案。業務条件・計算方式・導入条件は未確定。アプリ・DBの実装変更、実データ分析、最適化の効果検証は今回行っていない。

## 1. 目的と方針

**溶媒庫全体の指定数量倍率を運用上限内に収めながら、研究室の必要量を確保する保管量の配分を提案する。**

利用者から「指定数量を超過しないように在庫の最適化を行いたい。下限予測は現状実装している」と共有された。本計画の中心は、研究室×溶媒ごとの保管目標量と庫全体での両立可能性である。実装済みの下限予測を判断材料として使う。

補充については「年度の終わりなどの特定時期に、予算の余りを使い切るイメージで補充するらしい」と共有された。現場確認前の情報として扱う。この運用なら、**特定時期の一括入庫前に、庫全体の受入・保管量と到着時期を試算すること**を最初の利用場面にする。

管理者が現在の倍率を確認する業務から、出庫履歴・必要量・入庫予定に基づいて保管量を定期的に見直す業務への移行を目指す。まず根拠を確認できる提案・試算機能を作り、現場で効果を評価する。

| 区分 | 内容 |
|---|---|
| 利用者の希望として確認済み | 指定数量の超過を防ぐ在庫最適化。実装済みの下限予測を使う |
| 本計画の推奨案 | 年度末等の一括入庫前に、全研究室の入庫予定をまとめて受入・保管量を試算する |
| 現場で決める条件 | 運用上限、補充周期・所要日数、必ず確保する量、使用予定、容器単位、対象在庫の網羅性 |
| 今後の設計判断 | 目的関数、採用条件、保存・権限、入庫時の注意表示・制限の要否 |

## 2. 既存機能・要件との関係

- 対象は単一の溶媒庫内の全研究室在庫。[要件定義 §2](DXコア機能_要件定義.md#2-スコープ)と[ER図](ER図.md)に従う。研究室の居室・実験室の在庫は既存の管理対象に含まれない。
- 倍率・溶媒別内訳・指定数量未設定対象を読む[管理者集計](../supabase/migrations/20260929030000_admin_overview.sql)を再利用の起点とする。
- 現行ブランチにはSBA法で平均的な予測出庫量と下限までの余裕を表示する試行実装がある。[SBA設計](出庫量予測_SBA設計.md)。設計資料上、実Supabaseへの適用・実データ精度評価は未実施。
- 平均予測を、必ず必要な量・次回の出庫量・欠品しない量と同一視しない。使用予定や変動に備える余裕は本計画で検討する。
- [要件定義 F2-5](DXコア機能_要件定義.md#f2-下限の把握と予測)では発注の提案・自動化を対象外としている。本案は保管計画の参考情報とし、発注量の確定・自動発注は扱わない。目標量を発注量へ直接変換する場合は別途要件変更が必要。
- 初回リリースへの追加は未決定。[公開目標](開発前の合意・準備.md#5-現場確認と公開日)と、実データ蓄積・評価に必要な期間を分ける。

## 3. 上限と数量の定義

研究室×溶媒の在庫を添字 i、溶媒の指定数量を Q_i、現在量を A_i、提案する保管目標量を X_i とする。数量はLで扱う。

```text
現在倍率          R_now  = Σ(A_i / Q_i)
目標量の合算倍率  R_plan = Σ(X_i / Q_i)
計画の制約        R_plan ≤ C、かつ 0 < C < 1
```

複数種類の危険物はそれぞれの指定数量に対する倍数を合算する。[さいたま市の計算説明](https://www.city.saitama.lg.jp/001/011/001/p079650_d/fil/shouryou.pdf)。個々の法令値は[危険物の規制に関する政令](https://laws.e-gov.go.jp/law/334CO0000000306)と確認済みマスタを参照し、分類別の数値を固定しない。

**Cは大学側が確認した運用上限倍率。既存の `warning_ratio` とは意味を分ける。** 現行の0.8は早期警告の設定値で、最適化の上限として採用済みではない。Cは1.0未満の余裕を持つ値として管理者と決め、施設側により厳しい条件があれば反映する。この計算だけで施設の法令対応全体が確認済みとは扱わない。

- 指定数量が未設定・不正・未確認の在庫を無視して「上限内」と判定しない。規制対象外であることの確認と、単なる未設定を区別する。
- 対象に漏れがある場合は「登録済み範囲の参考試算」と表示し、庫全体の実行可能な計画にする前に網羅性を確認する。
- 同じ1 Lでも倍率寄与は溶媒で異なる。見直し対象を在庫Lの大きさだけで並べない。
- 下限値は注意表示のしきい値、保管目標量は保管計画の数量。別の値として扱う。

## 4. 最初に確認する情報

| 確認すること | 必要な理由 |
|---|---|
| 保管量を決める人・計画を確認する人 | 研究室の必要量と庫全体の配分を調整する担当者を決める |
| 運用上限C・記録対象の網羅性 | 全庫の制約を確定する |
| 年度末等の補充時期・臨時補充の可否・到着までの日数 | 次の補充機会まで備える期間と入庫ピークを決める。現行予測の7日を納期とは扱わない |
| 必ず確保する量・今後の使用予定 | 履歴の少ない対象や、まとめ出庫を必要量に反映する |
| 出庫できなかった必要量・欠品の影響 | 記録出庫だけでは分からない不足と研究への影響を把握する |
| 容器容量・開封状態・変更できる単位 | 小数Lの提案が実際に変更可能か確認する |
| 全研究室の一括入庫予定量・到着日・変更可能性 | 各室の予定を合算して入庫ピークを試算する。確定済みの数量と調整可能な数量を分ける |
| 予算利用・購入決定と保管計画の担当・期限 | 保管量の調整が間に合う段階を確認する。予算を使い切ることは最適化の目的には自動で設定しない |
| 出庫の意味・記録の継続性 | 訂正・調整等を区別し、記録漏れをゼロ出庫と混同しない |

まず運用の異なる少数の研究室・溶媒で確認票を作り、全研究室へ展開する。年度末等の特定時期に補充するという利用者情報は得られたが、正確な時期・頻度・所要日数・臨時補充の可否は未確認。年1回の補充と断定しない。

## 5. 機能の追加順

### 第1段階：見直し候補と手動試算

管理者が、現在倍率・上限との差・未設定対象、溶媒別の倍率寄与、出庫実績・予測の利用可否、必要量の確認状態を同じ画面で確認する。必要量を確認した対象について保管量の見直し候補を示し、目標量・入庫予定の仮入力で倍率変化を試算する。

最初の試算では、次の一括入庫に含まれる全研究室の予定量・到着日を集める。購入前/数量変更可能、購入済み/到着待ち等の状態を分け、計画を見直せる段階で現在倍率と入庫後の倍率を比較する。個々の入庫が小さくても合算で上限へ達する場合を検出する。

見直し案は `ΔR = 想定減量 / Q_i` と必要量への影響を併記する。最終出庫が古いだけで「不要」としない。履歴が少なければ「必要量の確認が必要」とし、予測不能な対象も現在倍率には含める。

同じ溶媒を庫内で研究室間移動しても倍率は減らない。見直しは実際の使用、入庫量・入庫時期の調整を通じて実現する計画として扱う。既存範囲外への移動で見かけ上の倍率だけを下げる案は作らない。

入庫前試算は現在の実在庫に予定入庫を足す保守的な計算から始める。予測出庫で空きが確保されたことにはせず、入庫前に実在庫から再計算する。

### 第2段階：研究室×溶媒の保管目標量を配分

- **必須量 M_i**：現場が確認した最低限確保する量。平均予測や既存下限値から自動確定しない。
- **希望量 D_i**：補充条件・使用予定・出庫変動を踏まえた保管計画上の希望量。推定の根拠と不確実性を残す。
- **調整単位 G_i**：容器等に対応する数量単位。自由に0.01 Lずつ変えられると仮定しない。

希望量は次の補充機会までの使用予定・出庫見通しを材料にする。特定時期のまとめ購入があることだけで出庫に季節性があるとは判断しない。現行の7日予測を単純に年単位へ伸ばして信頼できるとは扱わず、長い期間に備える量は実験予定や現場確認を重視して別に評価する。

最初の配分対象を**次の一括入庫で受け入れる量 P_i**とし、変更可能な予定量に対して試算する。購入・発注の自動決定は行わない。入庫前に出庫がない場合の保守的なモデルは次のとおり。式は検討用で、採用方式は未確定。

```text
入庫後量： X_i = A_i + P_i
必須条件： X_i ≥ M_i
全庫条件： Σ((A_i + P_i) / Q_i) ≤ C
受入条件： 0 ≤ P_i ≤ 予定入庫量、容器等の単位に対応する
固定条件： 変更できない予定量は固定し、計画で勝手に減らさない
評価量：   希望量の未充足 U_i = max(D_i - X_i, 0)

第1目的： 重要度を反映した希望量の未充足を小さくする
第2目的： 同等の未充足なら余分な保管量・変更負担を小さくする
```

重要度と、L単位の未充足をどう比較するかは運用側と決める。倍率寄与だけで必要な溶媒を優先的に減らさない。固定倍率の均等配分も、必要量との整合を確認する比較案に留める。

必須量だけで `Σ(M_i / Q_i) > C` なら**条件を満たす配分なし**と返す。上限や必須量を自動で緩めず、再検討する条件を示す。単純な候補比較で足りる段階はそれを使い、容器単位や組合せが必要になってから線形計画・混合整数計画等を選ぶ。

現在在庫と変更不能な入庫だけでCを超える場合も、次回受入量の配分だけでは解決できないと表示する。将来の保管目標量を現在量より下げる長期案は、実際の使用・入庫時期調整等を伴う移行案として別に扱う。予算上の希望数量と保管上限が両立しない場合は、その不一致を管理者へ提示する。

SBA等の平均予測は希望量の材料とする。変動に備える量は期間累積出庫の実績や将来分布を比較・評価して決める。一律20%等の上乗せを最適値・欠品しない量と呼ばない。使用予定を取り込む際は通常出庫予測との二重計上を防ぐ。

### 第3段階：入庫時期を含む計画と移行

目標量の合計が上限内でも、現在在庫・同時入庫で移行途中に上限へ達する場合がある。現在量、入庫日・量、出庫予定、入庫直後のピーク倍率を確認する。

出庫の確定分と予測分を分け、予測分だけに依存する案は条件付きとする。既存の指定数量監視と合わせ、入庫前に実在庫・他の予定入庫から再確認する。注意表示や入庫制限の要否は、この段階で業務要件として決める。

現在すでに上限へ達している場合は現在の状態と対応を先に示す。目標量を下げた試算を、現物の減量や超過解消として表示しない。

## 6. データ・画面・権限の設計方針

[ER図のテーブル説明](ER図.md#テーブル説明)は `inventory` を「研究室別の保有・管理対象」、`inventory_logs`を入出庫履歴、`operation_audits`を変更前後・理由の記録として定義している。現在量・下限値・履歴の意味を保ち、計画情報を拡張する。

| 情報 | 既存の利用 / 追加候補 |
|---|---|
| 現在量・研究室・溶媒・指定数量 | `inventory`、`rooms`、`solvents`と管理者集計 |
| 出庫実績・平均予測 | 有効な`inventory_logs.occurred_at`。訂正・取消後の品質確認を引き継ぐ |
| 運用上限 | 管理者用設定の追加候補。`warning_ratio`の意味を変えない |
| 必須量・希望量・補充条件・容器単位 | 在庫ごとの計画条件の追加候補。初期調査は確認票で整理 |
| 使用予定・入庫予定 | 研究室・一括入庫の対象期間・到着日・数量・状態・変更可能性・変更理由を持つ追加候補。予定と実績を区別 |
| 提案・確認・採用結果 | 計算日時、入力版、方式版、提案量、確認者・理由の保存候補 |

試算で`inventory.amount`を変更せず、計画の保存に入出庫履歴を流用しない。条件・計画の変更は監査対象にし、物理削除しない。正式なテーブル・列・RPCは項目確定後にER図・API設計へ反映する。本計画ではDBを変更しない。

入口は「管理→指定数量モニター→一括入庫の試算」を候補とする。スマホで対象時期・現在倍率・入庫後ピーク・必要量への影響を順に確認するカード構成とし、詳細は折りたたむ。5タブの構成に従う。

- **全体管理者**：全研究室の配分提案・研究室別見直し候補。
- **溶媒庫管理者**：全庫の倍率・溶媒別合算・入庫試算、自室の詳細。既存権限では他研究室の在庫・履歴の詳細を閲覧できないため、配分の詳細を公開するなら認可要件を先に見直す。
- **研究室ユーザー**：自室の在庫・予測。庫全体倍率・他室情報・管理者の配分情報は表示しない。将来自室の保管目標を示す場合もその範囲に限る。

結果には「現在」「計画上」「移行後」を区別し、対象漏れ・必要量未確認・配分不能・入力更新による計画の古さを示す。根拠は履歴期間・件数・予測方式・予定・必要量の確認状態とする。

## 7. 評価計画

実装時は合成データで、上限直前・境界・到達、指定数量未設定、同時入庫、容器単位の丸め、必須量が収まらない場合、予測不能、現物が目標量より多い場合を確認する。画面の丸め値で制約判定しない。権限・更新時の再計算・監査も検証する。

実データでは既存運用を続けながら提案と根拠を保存する試行から開始する。過去評価が可能なら当時利用可能だった履歴・訂正・予定・必要量だけを用いる。未来情報を混ぜない基本は[Forecasting: Principles and Practice §5.10](https://otexts.com/fpp3/toolbox.html#time-series-cross-validation)に従う。

年度末等の一括入庫を評価対象として、予定段階の試算で上限到達の可能性を発見できたか、実際の到着日に再確認できたかを追う。一括入庫後の長期間の必要量確保は、短期間の画面検証とは分けて評価する。

| 観点 | 指標 |
|---|---|
| 指定数量への効果 | 1.0以上の回数・継続時間、Cを超える時間、入庫直後の最大倍率、倍率の余裕 |
| 必要量への影響 | 出庫できなかった量・件数、実験への支障、緊急補充、必要量未確認対象の割合 |
| 在庫・負担 | 平均在庫、補充頻度、確認時間、提案の採用・保留・却下と理由 |
| 予測・適用範囲 | 累積出庫量の誤差、低頻度・まとめ出庫別の結果、提案可能な対象数 |

在庫が減っただけで効果を実証したとはしない。出庫できなかった量は出庫履歴だけから逆算せず、別に確認する。

現行運用、必要量を確認した手動目標、予測と制約を組み合わせた提案を比較する。シミュレーションは同じ需要・補充・容器条件を使う。記録出庫を需要の代用にする場合は欠品で観測が制限された期間等を明示する。合成検証と現場の超過削減を区別する。

採用基準は運用条件の確認後、比較結果を見る前に決める。上限を破る計画を採用可能としない、必須量を勝手に減らさない、必要量への悪影響を評価できることを最低条件とする。低頻度対象は暦の経過日数だけで評価を終えず、出庫・補充の事例数も見る。

## 8. 実施順序と成果物

| 工程 | 作業 | 成果物 / 次へ進む条件 |
|---|---|---|
| 1. 運用確認 | 上限・対象漏れ・次の一括入庫時期・必要量・容器単位を整理 | 確認票・計算条件表。全庫制約を定義できる |
| 2. 現状分析 | 倍率寄与・出庫傾向・記録品質・必要量を整理 | 見直し候補一覧。根拠と情報不足を区別できる |
| 3. 手動試算 | 全研究室の一括入庫予定を合算し、変更可能な量・到着日を試算 | 管理者が確認できる試算。必要量と上限の両立可能性を説明できる |
| 4. 配分モデル | 目的関数を決め、候補比較/最適化を試行 | 再現可能な計算・制約検証・現行/手動案との比較 |
| 5. 画面で試行 | Query・保存・監査・画面を追加 | 運用評価記録。提案と実在庫を区別できる |
| 6. 継続運用 | 上限到達・必要量への影響・負担を評価 | 適用条件、入庫時対応、正式要件への反映 |

条件確認・試算を先に進める。実データの頻度が未確認のため、効果検証の完了日は固定しない。

## 10. 根拠と限界

確認日2026-10-12。上記の要件定義・ER図・SBA設計・法令/自治体資料に加え、次を確認した。

- [ETH Zürich・安全在庫の教材](https://opess.ethz.ch/course/section-11-3/11-3-3-safety-stock-calculation-with-continuous-demand/)：需要・補充時間の変動に備える量の考え方を本文で確認。低頻度溶媒への特定分布式の採用根拠とはしない。
- [Oracleの容量制約の公式説明](https://docs.oracle.com/cd/E26401_01/doc.122/e48774/T473201T473217.htm)：容量を守る制約とサービス要求の関係を確認。ChemStockでは上限を緩和しない計画方針とする。製品やアルゴリズムの導入計画ではない。
- [Forecasting: Principles and Practice §5.10](https://otexts.com/fpp3/toolbox.html#time-series-cross-validation)：時系列評価の考え方。当時の訂正・予定状態の再現は別途設計する。

**今回整理したのは目標・既存設計との関係・必要情報・実施順序。適正在庫量の数値、最適化方式、超過防止の効果は未確定・未検証。**
