# 溶媒庫と研究室のモデル整合

- 日付：2026-09-28
- 状態：API・データ設計のモデルを統一済み。旧UIの部屋選択は別指摘として残る。DB移行・API実装は未実施。
- リポジトリ・版：ChemStock、`dxproject-2026`、ベース `63d6ca9`、未コミット。

## 目的と決定

API設計には`rooms.kind='溶媒庫'`の行を集計する記述と、溶媒庫ごとに権限を分ける記述が残っていた。一方、確定済みの要件では溶媒庫は単一で、`rooms`の1行はその内部の1研究室を表す。指定数量は全研究室の利用中在庫を合算し、溶媒庫そのものの行や`kind`列は設けない。

依頼者は、溶媒庫管理アカウントの研究室別在庫・履歴の操作を所属研究室のみにする案を選んだ。`accounts.room_id`は研究室・溶媒庫管理で必須、全体管理者ではNULLとする。指定数量の合算と通知は溶媒庫管理・全体管理者が全件扱える。

## 変更

- [API設計](../API設計.html)の集計条件、権限表、`GET /rooms`、指定数量モニターのパスと応答例を単一溶媒庫モデルに変更した。
- [ER図](../ER図.md)と[Draw.io図](../database/er-diagram.drawio)から未使用の`rooms.kind`を除き、アカウントの所属条件を明記した。[データ設計](../DXコア機能_データ設計.md)にも本番の研究室マスタ方針を追記した。
- [画面設計](../DXコア機能_画面設計.md)から複数溶媒庫の切替表示を除いた。[開発前の合意・準備](../開発前の合意・準備.md)、[実装タスク一覧](../実装タスク一覧.html)、[リリース計画](../開発準備・リリース計画.html)に所属・初期データの確認作業を反映した。
- `supabase/setup.sql`は旧デモ用であり本番に実行しないことをコメントで明記した。既存データの削除やスキーマ変更は行っていない。
