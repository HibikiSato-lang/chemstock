# 在庫Commandと指定数量通知の実装

## 成果と状態

基礎DBに続く2つのマイグレーションを追加し、入出庫、履歴訂正・取消、在庫下限値変更、利用停止を実データ画面からCommand RPCで保存できる構成にした。変更は再送キーで重複を抑え、DB内でアカウントと所属研究室を再確認する。訂正・取消・下限変更・利用停止には実操作者、理由、変更前後の監査記録を残す。在庫変更時の全研究室合算倍率をDBで再判定し、1.0以上への到達時に通知を生成する。

管理者向けQuery RPCも追加し、全室の合算倍率・内訳・未設定溶媒・通知一覧を画面へ接続した。通知の確認済み・対応済みへの変更Commandも接続した。コードと一時PostgreSQLでの検証は完了。実Supabase開発環境への適用、Auth・Data APIを通した画面操作は未実施。

## 目的と実施内容

研究室ごとの在庫操作と単一溶媒庫全体の指定数量監視を両立し、再送・権限外操作・競合で在庫と履歴や監査が食い違わないようにする。`private.execute_inventory_command` で再認可、共通ロック、再送キー、対象行ロック、更新、監査を一つのトランザクションにまとめた。`public.inventory_command` は公開DBロールからの入口とし、在庫表などへの直接DMLは引き続き許可しない。指定数量の再判定は文単位トリガーで行う。

画面では既存の5操作をRPCへ接続し、通信中は連続送信を抑え、失敗時にエラーを表示する。プレビューの下限変更・利用停止にも監査記録を追加した。管理者読取RPCはDB内で管理者ロールを再確認し、研究室アカウントへの全室倍率・通知の漏えいを防ぐ。通知変更Commandにも共通ロック、再送キー、状態遷移、監査を適用した。
