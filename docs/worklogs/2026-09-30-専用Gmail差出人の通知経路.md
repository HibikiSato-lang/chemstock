# 専用Gmailを差出人にする通知経路

## 成果と状態

大学ドメインの新規アドレスを用意できるか未確認で、既存の管理者用共有アドレスから送信できるかも未確認となった。依頼者は、大学アドレスを使えない場合にChemStock専用のGmailアドレスを差出人とする案を了承した。共有アドレスは受信先として維持する。[指定数量メール通知設計](../指定数量メール通知設計案.md)を更新し、専用Gmailアカウントで動くGoogle Apps Scriptの送信経路をローカル実装した。アカウント作成、Googleへの配置、実Supabaseへの適用、実送信は未実施。DBのメール設定は初期無効。

## 目的と判断

受信者が実際に見る差出人アドレスを管理できるようにする。既存の大学共有アドレスから送信できる場合はその権限を使い、難しい場合でも専用Gmailアドレスを明示した通知を送れるようにする。表示名を「ChemStock 溶媒庫通知」とし、返信先を管理者用共有アドレスにする。表示名や返信先は`From`の実アドレスを変えないため、試験受信で両方を確認する。

Google Apps Scriptの`MailApp`を選んだ理由は、専用アカウントをスクリプトの実行主体にし、表示名と返信先を設定できるためである。直接Gmail APIを使うOAuth方式もあるが、今回のローカル実装はApps Scriptを選んだ。個人GmailのApps Scriptには送信先数の割当があるので、通知頻度を実運用前に照合する。

## 実施内容と安全条件

- Edge Functionの`EMAIL_PROVIDER`に`gmail_apps_script`を追加した。Googleスクリプトの送信者を配送記録の差出人と照合し、固定宛先を送信前に確認する。結果不明時は自動再送しない。
- [Code.gs](../../supabase/functions/send-notification-emails/google-apps-script/Code.gs)は専用アカウントの実行主体、長い共有トークン、登録済みの受信先を確認してから`MailApp.sendEmail`を呼ぶ。受信先以外には送らない。
- [Supabaseの手順](../../supabase/README.md)に、専用GmailアカウントのScript Properties、Edge Function Secret、Webアプリ配置、試験受信を追加した。
