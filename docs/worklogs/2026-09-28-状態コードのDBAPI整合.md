## 目的と判断

[API設計](../API設計.html#3-1-ベースurlとデータ形式)は履歴状態を`active` / `cancelled`、通知状態を`unread` / `acknowledged` / `resolved`としていた。一方、[データ設計](../DXコア機能_データ設計.md)の欠品予測SQLは`status='有効'`、通知バッジSQLは`status='未確認'`を検索していた。DBにAPIの英語コードを保存すると、どちらも対象行を拾えない。

初回リリースではDB保存値とAPI送受信値を同じ英語コードとし、日本語は画面の表示名に限定する。通知種別も`designated_quantity_exceeded`に統一する。DBのCHECK制約・部分ユニークインデックス・トリガー・欠品予測・未確認件数集計を同じコードで定義する。

## 検証と根拠

- 作業ディレクトリ：`/Users/deckz/chemstock`。`git diff --check`は問題なし。更新したHTMLをPythonの`html.parser`で、draw.ioファイルをXMLパーサーで読み込んだ。`rg`で文書中の日本語状態値をDBの比較リテラルとして残していないことを確認した。
- PostgreSQL 17.5の一時DBに、データ設計のDDL・ビュー・トリガー・欠品予測のSQL例を適用した。合成在庫に`active`出庫3と`cancelled`出庫30を入れ、予測の日次平均は`0.1`（3÷30）だった。倍率が1.0以上になる更新で通知`designated_quantity_exceeded:unread`が1件でき、未確認件数は1。`resolved`後、1.0以上のままの更新では通知は増えず、1.0未満へ戻して再到達すると合計2件になった。日本語の`有効`を履歴に挿入するとCHECK制約で拒否された。一時DBは停止・削除した。
- テストは最小限の合成スキーマと`auth.uid()`代替関数を使用した。Supabase Authや製品スキーマの統合検証ではない。
