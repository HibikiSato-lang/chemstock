## 目的と実施内容

画面一式のコードレビューで、Supabase接続設定がある環境では未ログインの `/preview` が認証判定によりログイン画面へ転送されることを確認した。画面確認用データはブラウザー内で動作し、実データへの更新も行わないため、[認証処理](../../lib/supabase/proxy.ts)の入口で `/preview` とその配下だけを通過させた。接頭辞が同じ別ルートを通さないよう、完全一致または `/preview/` から始まる場合に限定した。通常画面とAPIの認証判定は維持した。

## 検証

- `npx eslint lib/supabase/proxy.ts`：成功。
- `git diff --check`：成功。
- `npm run build`：成功。
- ダミーの `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` を設定して Next.js 開発サーバーを起動。未ログインの HTTP 要求で `/preview` と `/preview/inventory` は 200、`/protected` と `/previewish` は `/auth/login` への 307 転送を確認した。実Supabaseへの通信は行っていない。

## 限界と次の作業

実Supabase環境の有効なセッションと併用した動作は未確認。次はコードレビューで指摘された履歴200件上限による欠落と集計誤りを修正する。

## 発表・報告に使える要点

画面確認用ルートの認証境界を明示し、接続設定がある状態でも未ログインでプレビューを開けること、通常画面の未ログイン転送が維持されることをローカルで確認した。
