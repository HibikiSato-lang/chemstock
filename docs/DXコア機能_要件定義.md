# DXコア機能 要件定義（指定数量監視・欠品予測）

本書は [DX構想](DX構想.md) で決定した**デジタライゼーションのコア2機能**に限定した要件定義である。
システム全体の要件定義（`DXプロジェクト_要件定義_非機能要件.docx`）とは**別文書**であり、
全体要件と矛盾が見つかった場合は全体要件を正として本書を改訂する。

関連文書：[画面設計](DXコア機能_画面設計.md) / [データ設計](DXコア機能_データ設計.md) / [ER図](ER図.md) / [UI案](UI案.md)

---

## 1. 背景・目的

- 現状、消防法の指定数量倍率の確認は人の手計算・目視点検に依存しており、漏れ・遅れが起きうる。
- 溶媒の残量把握も「見た人の経験と勘」に依存しており、欠品に気づくのが遅れる。
- 本機能により、**「記録を人が見て判断する」を「システムが判断して人に通知・提示する」に変える**
  （デジタイゼーション → デジタライゼーションへの移行。位置づけは [DX構想](DX構想.md) §1）。

## 2. スコープ

### 前提：対象は溶媒庫のみ（2026-07-19 確定）

本システムの在庫管理対象は**溶媒庫のみ**である。溶媒庫の内部は**研究室ごと**に分かれており
（`rooms` の1行＝1研究室）、在庫・入出庫はすべて「研究室×溶媒」で記録する。
研究室が自室（居室・実験室）で保管する溶媒は**対象外**（システムに記録しない）。
操作・閲覧対象の研究室は**ログインアカウント（`accounts.room_id`）から自動決定**し、研究室ユーザーに研究室選択UIは出さない。
数量の単位は **L／ガロン／斗缶** を入力・表示で扱い、内部は `base_unit` に換算して保持する（換算値は `settings`。F2-6・ER図参照）。

### 対象

| # | 機能 | 概要 |
|---|---|---|
| F1 | 指定数量監視 | 溶媒庫全体（全研究室）で指定数量の倍数を常時集計し、しきい値超過を通知する |
| F2 | 欠品予測 | 直近の消費ペースから「下限割れ予測日」を算出し表示する |

F1・F2とも初回リリースに含める（F2は2026-09-25に初回対象と決定）。

### 対象外（本書では扱わない）

- 発注・購買の提案や自動化（[DX構想](DX構想.md) の方針として対象外）
- 通知のエスカレーション、監査レポート自動生成、SDS連携、保管期限管理（中期ロードマップ）
- 入出庫・取消・編集そのものの仕様（既存要件定義の範囲）
- **在庫下限（残量低下）の通知**：本機能では `notifications` として実装しない（§2.1 の決定）
- **メール・SMS・プッシュ通知**：初回リリースでは実装しない。指定数量超過のメールは初回後の追加候補

### 2.1 通知の対象範囲（決定）

本機能で扱う「通知」は**指定数量系（管理者向け）に限る**。在庫下限（実際に `amount ≤ low_stock_threshold` となった状態）は
システム通知（`notifications` レコード）としては持たず、研究室が**自研究室のホームバナー（欠品予測 F2）**および
**在庫表示（一覧の ⚠・詳細の下限値）**で把握する。

理由：欠品予測（F2）が事後の下限割れ通知の上位互換であり、また管理者が全研究室の下限割れを監視するとノイズが大きく、
指定数量（溶媒庫全体の法令リスク）とは重要度が異なるため。

通知種別・関心事の主体・到達手段の全体像は次表を正とする。

| アラート種別 | 発生条件 | 関心事の主体 | 到達手段 | `notifications` |
|---|---|---|---|---|
| 指定数量接近（状態表示） | 溶媒庫の倍数 ≥ warning_ratio(0.8) かつ 1.0 未満 | 溶媒庫管理＋全体管理者 | 指定数量モニターの警告色表示のみ | なし |
| 指定数量超過 | 溶媒庫の倍数 ≥ 1.0 | 同上 | アプリ内通知一覧＋未確認バッジ＋指定数量モニター | あり |
| 欠品予測（F2） | 自研究室在庫に下限割れ予測日あり | 研究室（自研究室） | ホームバナー＋グラフ | なし |
| 下限割れ中（状態表示） | 自研究室在庫 `amount ≤ 下限` | 研究室（自研究室） | 在庫一覧 ⚠＋詳細＋ホームバナー状態 | なし |

## 3. 用語

| 用語 | 定義 |
|---|---|
| 指定数量 | 消防法令が危険物ごとに定める基準量。`solvents.designated_quantity` に保持 |
| 倍数 | 貯蔵量 ÷ 指定数量。複数溶媒は倍数を合算する |
| 警告倍率（warning_ratio） | 倍数がこの値**以上になったら画面上で接近表示する** ChemStock 独自のしきい値（既定 0.8）。通知発火条件ではなく、**法令基準でもない** |
| 下限割れ予測日 | 現在の消費ペースが続いた場合に在庫が `low_stock_threshold` に到達すると予測される日 |

## 4. 機能要件

### F1 指定数量監視

| ID | 要件 |
|---|---|
| F1-1 | 溶媒庫全体で、利用中（`is_active=true`）在庫の `Σ(amount ÷ designated_quantity)` を集計する（在庫はすべて溶媒庫内の研究室にあるため全在庫が対象）。`designated_quantity` 未設定の溶媒は集計から除外する |
| F1-2 | 在庫量が変化するすべての経路（入出庫・取消・編集・利用停止、**および在庫行の新規作成＝新規溶媒の初回入庫**）で再判定する |
| F1-3 | 倍数が warning_ratio（既定0.8）以上1.0未満の場合は指定数量モニターを「接近」表示にするが、通知は作らない。1.0 **以上になったら**「指定数量超過」として `notifications` に記録する（境界値ちょうどを含む＝`≥`） |
| F1-4 | 初回リリースでは指定数量超過をアプリ内通知一覧・未確認バッジ・指定数量モニターから確認できるようにする。メール・SMS・プッシュ通知は初回対象外とする |
| F1-5 | 未対応（未確認/確認済）の「指定数量超過」通知が残っている間は、新規通知を発行しない（重複抑制） |
| F1-6 | 倍数がしきい値未満に戻っても通知を自動で消さない。管理者が「対応済」にステータス変更する（変更は監査記録の対象） |
| F1-6b | **再通知はヒステリシスで制御する**：「指定数量超過」を「対応済」にした後は、倍数が**1.0未満まで一度戻り、再度1.0以上に到達したとき**にのみ再通知する。1.0以上のまま「対応済」にしても、直後の在庫変動では再通知しない |
| F1-7 | 管理者は現在の倍数・溶媒別の内訳を画面（指定数量モニター）でいつでも確認できる |
| F1-8 | 倍数・指定数量通知は**溶媒庫管理・全体管理者の全員が全件を閲覧できる**（溶媒庫は単一のためスコープ分けはない）。通知一覧・未確認バッジ・指定数量モニターも同様。**研究室ユーザーには一切表示しない** |
| F1-9 | 管理タブおよび管理者画面に**未確認件数バッジ**（`status='未確認'` の件数、F1-8のスコープ準拠）を表示する。管理者は画面で通知と現在の倍率を確認できる |

### F2 欠品予測

| ID | 要件 |
|---|---|
| F2-1 | 在庫ごとに、直近N日間（設定値、既定30日）の出庫実績（有効な `inventory_logs` の負の `change_amount`）から1日あたり平均消費量を算出する |
| F2-2 | `(amount − low_stock_threshold) ÷ 日次平均消費量` から下限割れ予測日を算出する |
| F2-3 | 予測日をホーム画面のお知らせバナーおよびグラフ画面に表示する。表示対象は自研究室（自分の `room_id`）の在庫のみ |
| F2-4 | 次の場合は予測を表示しない：期間内に出庫実績がない／`low_stock_threshold` 未設定／既に下限割れ。**既に下限割れの在庫はホームバナーに「下限割れ中」の状態を表示する（予測日は出さない）**。これは画面表示であり、`notifications` は発行しない（§2.1） |
| F2-5 | 予測は「見通しの提示」まで。発注の提案・自動化は行わない |
| F2-6 | 予測値の算出はすべて基準単位（`base_unit`）で行い、表示時のみ単位変換する |

## 5. 非機能要件（本機能に固有の分）

| 項目 | 要件 |
|---|---|
| 性能 | 倍数集計・欠品予測は画面表示を体感で妨げないこと（在庫・履歴データはたかだか数百〜数千件想定であり、集計クエリで十分） |
| 通知反映 | 在庫変化と同一トランザクションでアプリ内通知を作成し、次回の画面取得時に表示できること |
| 整合性 | 超過通知の判定と記録は在庫更新と同一トランザクションで行い、判定漏れを起こさない |
| 監査 | warning_ratio・予測期間などの設定変更は `operation_audits` に変更前後と理由を記録する |

## 6. 制約（既存方針の継承）

- 既存画面のフロー・コードは変更しない。新機能は**差分追加**（バナーへの行追加・管理者画面への項目追加等）として実装する。
- スマホ前提・スクロール最小化（下部タブ／プルダウン／折りたたみ）。
- 指定数量・危険物分類の数値をアプリコードにハードコードしない（`solvents` テーブルの値を正とする）。
- warning_ratio(0.8) を法令基準であるかのように文言表示しない。

## 7. 前提・未確定事項

| # | 事項 | 現時点の扱い |
|---|---|---|
| 1 | 研究室が自室で保管する危険物溶媒の扱い | **対象外で確定（2026-07-19）**。自室保管分はシステムに記録しないため合算にも含まれない。溶媒庫内は全研究室を合算する |
| 2 | 予測期間N日の既定値 | 30日で開始し、運用しながら `settings` で調整 |
| 3 | 在庫履歴が参照期間Nより短い在庫の予測 | 日次平均は「消費総量 ÷ N（固定）」で算出するため、**登録から日が浅い在庫は消費ペースを過小評価し予測日が楽観的**に出る。F2-5の「見通しの提示」の範囲として許容する（断定表現を避ける文言運用でカバー） |
| 4 | 初回の通知確認方法 | 日常点検は前提にせず、管理者が次にアプリを開いた時に通知を確認・対応する。アプリを開くまで気付けないことは依頼者が2026-09-27に了承。実際に対応する管理者への共有・確認は未実施 |
| 5 | 指定数量超過メール | 初回後の追加候補。導入時期・送信先・差出人は後で決める |
| 6 | 本番開始時の履歴 | 既存の仮の在庫・入出庫履歴は引き継がず、研究室が確認した初期在庫から始める。出庫実績ができるまでF2の予測日は表示されない（依頼者が2026-09-27に了承。チーム確認は未実施） |

## 8. 受け入れ基準（抜粋）

- 溶媒庫の倍数が0.8以上1.0未満になっても通知は生成されず、指定数量モニターだけが「接近」表示になる。
- 溶媒庫の倍数が1.0以上になったとき、1件だけ「指定数量超過」のアプリ内通知が生成され、未確認バッジに反映される。
- 通知が未対応のまま在庫をさらに操作しても、通知は増えない。
- 研究室ロールでログインした画面のどこにも倍数・指定数量通知が表示されない。
- 直近30日に出庫実績のある在庫について、ホームに「○月○日 下限割れ予測」が表示され、出庫実績のない在庫には表示されない。
- 予測表示は自研究室の在庫のみに出る。
- 在庫が下限を割っても `notifications` レコードは生成されず、ホームバナーには「下限割れ中」の状態表示のみが出る。
- 溶媒庫管理・全体管理者のどちらでログインしても、指定数量通知の全件が見える。
- 管理タブ／管理者画面の未確認バッジが、スコープに応じた `status='未確認'` の件数を示す。
